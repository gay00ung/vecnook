# Storage validation and remaining release gates

The 1.0 candidate includes explicit failure-point tests around standard-library
I/O. Test controls are thread-local and compiled only under `cfg(test)`; the
published library has no environment-controlled fault injection.

| Failure point | Expected and checked result |
| --- | --- |
| Short/interrupted WAL writes | `write_all` retries; the acknowledged batch reopens completely |
| Partial WAL batch at every byte boundary | Old acknowledged records survive; none of the incomplete batch members apply |
| WAL sync failure after write | Handle is poisoned; reopening can reveal a whole persisted batch despite the returned error |
| Snapshot write/sync/rename | Old snapshot plus WAL preserves acknowledged records |
| Directory sync after snapshot rename | Handle is poisoned; snapshot/WAL reconciliation preserves records |
| Cache write/sync/rename | Authoritative snapshot/WAL survives; a missing/invalid derived cache rebuilds |
| WAL truncate/clear sync | A durable checkpoint still represents all acknowledged records |
| Backup copy/sync | Source remains usable; incomplete backup is rejected and never overwrites another directory |
| Export partial write/sync | Source remains usable; incomplete archive is rejected before import creates a directory |

The suite also mutates snapshot/WAL/header lengths, bytes and checksummed fields
with reproducible seed `0x20261006`. Read-only diagnosis never changes those
inputs or panics. Existing tests validate every cache truncation, invalid cached
graph bounds, document payload truncations, duplicate IDs, sequence gaps and
actual process interruption. A future authoritative snapshot version is rejected
before repairing even an incomplete WAL tail.

The 0.3.0-beta.2 upgrade fixture is generated by its actual registry-installed CLI,
with authored source text. It contains a checkpointed graph and a later atomic
update/delete WAL batch. New code validates its identity, searches original
documents, writes changes, checkpoints, backs up, exports and imports it.
Actual 0.1.0 and 0.2.0 source binaries, built from commits `66b0dde` and `aa74b2f`, generate the older vector fixtures. Their post-checkpoint updates/deletes also open, mutate, checkpoint and back up with the new reader. Fixtures are public authored
test data, never user documents or model weights.

## Mixed workload runner

```bash
cargo build --release --offline --example soak
target/release/examples/soak data/soak-short 0 100000
target/release/examples/soak data/soak-24h 86400 100000
```

Use a new directory for each run. The runner persists mixed inserts, replacements,
deletes and atomic batches; it logs only successful acknowledgements to a synced
`ack.tsv`. It independently replays that log, compares every visible vector/text
record, checks exact Top-K against its own distance oracle, compacts, reopens and
verifies independent backups. `progress.json` records actual elapsed time,
acknowledged mutation count and completed verification counts. Both elapsed-time
and mutation gates must pass; a quick 100k run is not a 24-hour result.

A final 1.0 release still requires a completed 24-hour run on the release
candidate and real Windows 11 installation/ownership/restart/backup checks.
Windows Server NTFS CI is useful evidence and is reported as such; it does not
substitute for Windows 11. Hardware power loss and network filesystems remain
outside the validated scope. Report corruption with version, filesystem,
reproduction and preserved original files through the project's issue paths.
